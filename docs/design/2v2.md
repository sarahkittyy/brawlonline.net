# 2v2 queue

_2026-11-02, Sarah's board card ("Play 2v2" button). Decisions are Sarah's unless marked **proposed** (a default nobody has confirmed yet)._

**Built (2026-11-02; the pair room 2026-11-03, below):** the server (mm queue, parties, splits, ratings: e715c08a), Dolphin, the plugin and the launcher. Where it differs from below: WITH ANYONE is Brawl's three-button page (the one WITH FRIENDS opens) labelled UNRANKED / RANKED / 2V2, not three thinner bars; the open partner panel's plate says "A: Enter Code" (the plates' font has no brackets); the match history has 2v2 since 2026-11-03 (its own filter; your games won - lost, the others' wins).

## Shape

- A queue like Unranked, not a matchmade room: lock in on the CSS, wait in the training room, the match starts when four players are found. Random stage from the pool, P+'s **rainbow** team battle with the team glow (`TEAMS_RAINBOW`, `gmSelCharData+0x33` = 2), never the teams' costumes.
- Why not a room: rooms pick characters after joining (an AFK stranger holds three people before game 1) and every host control (kick, slots, Teams, rules, sets, sit-out, loser picks) would have to be locked.
- What exists: Dolphin already connects 3-4 players from a ticket (every pair direct, `GameplayOnlineBackend.cpp`), `MaybeDecideSetup` already sets up rainbow teams, `Engine::make_match` takes any number of tickets.

## Entry points

- Launcher: **Play 2v2** right of Play ranked, with its own "N in queue · M in game".
- In game: WITH ANYONE gets three entries, each shorter so they fit: **UNRANKED, RANKED, 2V2**.
- Either one lands on the **2V2 CSS** with the player's own party open: their panel and an empty partner panel.

## The party (0-1 partner)

- A party is a private 2-slot room on mm (rooms' join/leave/announce/invite), with its own 4-letter code (room-code alphabet) shown in the CSS header where a room shows its code. Never in the public room list.
- Empty partner panel: **"OPEN" / "(A) Enter Code"**. A opens the keypad in room-code mode with the hint line "Enter your partner's 2v2 code". A code joins that party; the joiner's own (empty) party closes.
- The launcher's envelope (invite button) becomes **"Invite to your 2v2"** while the player is in 2v2; accepting puts the friend's game on the 2V2 CSS in the inviter's party. The launcher's Join box takes a party code like a room code.
- No separate queue / invite / join buttons: everything is the CSS's partner panel or the existing envelope.
- The partner panel shows the partner's character, name and Ready, as room panels do.
- **Join races** (mm handles party requests one at a time, in arrival order):
  - A and B enter each other's codes at once: the first request processed wins (A joins B's party, A's party closes). B's request then names a party that is gone, but its owner is already B's partner, so it **succeeds as a no-op** ("already together"), never an error.
  - Two players enter the same code at once: the first fills the slot, the second gets "Party is full" and stays in their own party.
  - An invite accepted while a code join to the same party is in flight: the same rule, the first fills it, the second is a no-op if it's the same person, else "Party is full".
  - Entering a code while you already have a partner: impossible from the CSS (no open panel); from the launcher it asks to leave the current partner first.
  - Your own code: ignored. A code of a party that is searching: the join stops the search, both back on the CSS ("B joined"), unlocked joiner. A party whose players are in a match: "In a game - try again after".
- Partner leaves the party (B out of the CSS): the slot opens again, "B left".

## Searching

- START locks in. Solo: searches at once. Pair: searches once both are locked in.
- Training room banner: **"2V2 - Searching..."**, or **"2V2 - Searching with B..."** for a pair, in the format of the UNRANKED banner. Hold START cancels; in a pair it cancels for both ("B cancelled"), both back on the CSS together.
- mm groups four tickets: the oldest and three others with every one of the six pairs inside the ping limit, then the rating band. Pairs vs pairs first, a pair vs two solos after some waiting.
- Found: "2V2 - Connecting...", then, as Ranked, back on the CSS for game 1 (2026-11-03, Sarah: "like in ranked, when you match up with someone, you're taken back to the css, where you can see this window-- usernames, teams, and everyone can pick their character and see what everyone else picked"): the four panels (below), the 45 s ready-up, START readies. The search's character is only the waiting room's. Someone leaving before game 1 sends everyone back to searching. A failed connect: everyone stays in the room and searches again ("2V2 - Couldn't connect - Searching..."); mm does not group the failing pair again. Expect more failures than 1v1 (six pairs must connect; no relay).

## The pair room

_2026-11-03, Sarah's board ("how difficult would it be to let two doubles players queued together in the same room swing at each other in the training room?"). Built the same day._

Sarah's rules:
- Two partners searching together play the waiting room together: connected once both search, an identical start, no time or stock limit.
- No replays, no spectating; they count only in the queue numbers.
- No pause menu and no L+R+A+START prompt: either player holds START (half a second, as in the waiting room) and both are back on the party's CSS, out of the queue.
- The pair room is abortable at every step of its start: a match found while it connects must never race any step of it.
- Partners who cannot connect to each other would not connect in the match either: the Direct / room connection error ("Couldn't connect to bob.") and both are out of the queue.
- Time mode with no time limit, not 99 stocks (Sarah: "p+ has a mode ... timed mode, set the time to infinite"); the waiting room's banner stays, drawn client side.
- Straight in, no solo room first ("after readying up, it takes you to the singleplayer training room for just a second, and only THEN puts you in with your partner. the solo room should be skipped entirely"), the waiting room's song, and no 3-2-1 countdown ("can we cleanly remove that from just this training room thing?").

How it works:
- **mm** (`rooms.rs` `pair_ticket`): a party whose two players both search, both games having said `hello.pairRoom`, says `pairRoom` in its room state. Each game then sends a party ticket (mode 3 naming the party's code) beside its 2v2 ticket; the two are matched with each other only (`docs/rooms-protocol.md`): the party's slots as ports, the party's host deciding, the Training Room, time with no limit, no items. A pair with an older game in it plays today's solo rooms.
- **Dolphin** (`Online/OnlineClient.cpp`, "The pair room"): a second matchmaking for the party ticket, on its own port (the forced port + 1 when one is forced) and its own UPnP mapping, handed off as a session of its own (`ConnectOptions::pair_room`: no replay, so nothing is spectated or reported; no game result; Ranked's quality abort and desync recovery off). It ends at once wherever it is when the 2v2 search no longer waits for its match: its party ticket's matchmaking is dropped, a hand-off that comes later finds its generation gone and drops the link, and a session of it is stopped; the 2v2 match's own hand-off ends it too and waits for its match to be over first, and the next session waits for the game to leave that match's scene (`await_scene_exit`). GameBridge does not run while a match runs, so a thread of its own checks the search every 50 ms. The pair room's own end ends the search: a hold START quietly (the machine whose session ended first leaves the other's, which then reads SESSION's quitBy), a desync ("Out of sync with bob."), a party ticket that timed out connecting ("Couldn't connect to bob."), the partner gone ("Lost the connection to bob.", only if no match comes within 1.5 s: a partner whose search found the match leaves the pair room first). A 2v2 search that fails while the party ticket connects or its session plays waits the same 1.5 s for the pair room's own outcome, so a partner's hold START or failed connect is not "bob cancelled".
- **The game** (SESSION mode `MODE_PAIR`, 6): a pair whose partner's game plays the pair room (the room state's slot `pairRoom`, SESSION's `SLOT_PAIR_ROOM`) waits on the party's CSS once both search ("Connecting to bob..."), and leaves for the pair room's match once SESSION has its setup (game 1), the screen fading out first; it goes to the waiting room alone only if the partner's game does not play it or the pair room is not there 12 s after both search (it then ends into it from there). The match is an online match on the Training Room with the room's song (X07, as the room forces it) and its Sandbag (asked for at game frame 30, made at 130, after the session's start, where every machine has its archive: made as soon as the archive was there, it came a frame or two apart on the two machines, and they desynced later), no pause, no quit hint, START held 30 frames ends it for both (the client pause's quit), and the waiting room's banner, a dark band with "2V2 - Searching with bob... - Hold START to cancel" moving through it (MatchHud, drawn only, placed by the game frame). It has no countdown: the match's ready-go operator only starts the song as soon as it is ready (the countdown's start does that in a match: without it the room had no music, Sarah: "i don't hear the music?"), and does nothing else until game frame 100, when every fighter exists, then only what GO does besides its graphics and sounds (each player's loader started, the fighters started, the stage told each step), and is over; the screen stays black until the session's start (frame 120), when the players can move. The session gone (the match found, the search over) ends the match quietly (LOCAL quitLeft). Back on the CSS, a search that goes on waits for the pair room again; one whose four connected builds the CSS again with the four panels.
- Tests: `harness/tests/test_twos_pair_room.py` (both in, the banner, the queue counts, matching checksums, hold START; partners who cannot connect, `PPR_TEST_PAIR_NO_P2P`), `test_twos.py` `test_twos_pair_and_two_alone` (the pair room until the match is found), `test_twos_pair_found_at_once` (the match made as the pair starts), `test_twos_pair_found_while_its_room_starts` (found between the partners' connect and their session, `PPR_TEST_PAIR_HANDOFF_DELAY_MS`).

## Teams

- Game 1: mm's most even split by 2v2 MMR. Every later game the teams **shuffle**: never the last game's split, the most even of the others. Pairs always stay on one team, so a pair with two solos, or two pairs, never shuffles.
- Just before the load: **"A & B vs C & D"**, the player's own team first (one line for short names, two lines at 0.7, "A & B" / "vs C & D", up to the 15-character names).

## Between games (same four)

- The CSS (before game 1 too) shows the four players' panels as a room's: each player's name, the character on their CSS (their coin until they ready, then READY) and the team colours of the next game. The teams are shown only; nothing on the CSS changes them. Every machine knows them before the game is set up: game N's split is a function of N alone (game 1 the most even, then alternating).
- Back on the CSS (not the training room): "Press START to ready (45)", counting down. Characters may change first; B before readying takes it back. "Waiting on: A, B", then "Ready 3/4".
- All four ready: the host draws the new split and the stage, "A & B vs C & D", the game.
- Someone not ready within 45 s (**proposed** length): removed to the idle CSS ("Removed - didn't ready in time"), must lock in again. The others who readied go back to searching ("A didn't ready - Searching...") with their old place in the queue (mm usually regroups them with one new player). A pair stays a pair; a pair whose partner timed out goes back to the CSS together.
- Someone leaves the CSS (B): as a timeout ("A left - Searching..."); those not yet ready stay on the CSS with "A left - Press START to search".

## In a match

- One player quits or disconnects: their fighter is despawned, the HUD shows "A left" in red, the other three play it out. Afterwards the rest search again.
- A whole team leaves: the match ends ("Opponents left - You win"), the leavers' team loses.
- Frozen 30 s = left. Desync: not rated, back to the CSS to ready up (Unranked's rule). Ties: sudden death as now; a draw is half a win.
- Pause: **proposed** none (one pause stops three others). A player **out of stocks** may leave at any time (hold START for a second, no pause screen) and gets the team's result, not a loss (Slippi's `PreventDeadStranding` lets dead players out too).

## Rating

- Its own hidden **2v2 MMR** per player (**proposed**), seeded from the player's Unranked MMR. Expected score: own team's average against the other team's, from the teams as they started the game; both teammates move by the team's change. A pair queueing together counts slightly above its average (**proposed**).
- Leavers always take a loss, except a player already out of stocks (above). Everyone else is rated by the result: winning a 1v2 is a win, the teammate who left still loses.
- 2v2 game reports never feed the 1v1 Unranked MMR.
